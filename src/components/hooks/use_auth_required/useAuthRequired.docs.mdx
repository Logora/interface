This hook dispatch a custom event to signal authentication.

### Component usage
```js
import { useAuthRequired } from '@logora/debate.hooks.use_auth_required';
```
```js
const Component = () => {
	const requireAuth = useAuthRequired();

	return (
        <>
            {requireAuthentication({})}
        </>
    )
}
```
### Subscribers-only modules

Inside a `ModuleContext.Provider` (for example `value="comments"`), when `config[module].subscribersOnly` is `true` and the logged-in user's `is_subscriber` is not `true`, `requireAuthentication` shows `SubscriptionModal` with `config[module].subscriptionModal` instead of the login flow. `useSubscriptionRequired()` returns that condition.

Visitors (not logged in) on such a module also get `SubscriptionModal` first, with an « Already a subscriber ? Sign in » (`auth.sso_form.already_subscriber`) link that switches to the usual login flow (login events, then `AuthModal` unless `disableLoginModal`). `useSubscriptionRequired()` only covers logged-in users.

In that case the hook dispatches a `logora:subscription:requested` window event (`detail`: `{ module, redirectUrl }`) before showing the modal. With `config.auth.disableSubscriptionModal: true`, only the event is dispatched, so the client can open its own subscription page, as `config.auth.disableLoginModal` does for login.

A visitor always gets the usual login flow (events, then `AuthModal` unless `config.auth.disableLoginModal`).

Administrators are exempted by the API but not by this hook, since the current user payload does not expose an admin flag: a non-subscriber administrator sees the subscription modal.
